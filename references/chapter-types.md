# 章节类型模板库（v2.0）

> **核心规则**：chapter-writer 在动笔前**必须先选 chapter_type**，再选对应结构。
> 同一章只能选一种 type（不允许"既基础概念又方法论"）。
> 6 种 type 覆盖了所有思想体系章节的可能形态。

## 目录

- 0. 选 type 决策树
- 1. 基础概念（concept）
- 2. 方法论（methodology）
- 3. 行业判断（industry-analysis）
- 4. 案例分析（case-study）
- 5. 心境反思（personal-reflection）
- 6. 哲学总纲（philosophy-overview）
- 7. 章节类型 → 数据字段映射
- 8. 反模式速查
- 9. 历史教训

---

## 0. 选 type 决策树

```
这一章主要在解释什么？
│
├─ 解释一个底层原理/概念怎么工作
│  └─ → 基础概念
│
├─ 介绍一套可复用的方法/步骤
│  └─ → 方法论
│
├─ 对某个市场/产品/公司做判断
│  └─ → 行业判断
│
├─ 讲一个完整的"问题-方案-结果"案例
│  └─ → 案例分析
│
├─ 谈作者自己的一段心路/成长
│  └─ → 心境反思
│
└─ 给出顶层世界观/哲学/第一原理
   └─ → 哲学总纲
```

**判断不到？** 默认选"方法论"（最通用），但 critic 会在 `chapter_type_consistency` 检查里报警。

## 1. 基础概念（concept）

### 适用场景
- 解释一个技术/商业/社会现象的底层原理
- 例：示例创作者甲《AI 宇宙的技术底座》、任何"XXX 是什么"章

### 结构骨架（6 节）

```markdown
### X.0 概念定义（【原话】+【蒸馏】）
- 作者对概念的核心定义（≥ 1 段原话）
- 与相似概念的区别（蒸馏）
- 这条定义为什么对读者重要

### X.1 类比与直觉装置（【蒸馏】）
- 把抽象概念翻译成读者秒懂的画面（如"数据是食材、模型是菜系、训练方法是厨师"）
- 至少 1 个强类比

### X.2 三大支柱 / 核心结构（【原话】+【蒸馏】）
- 把概念拆成 3-5 个组成部分
- 每个部分配 1 段原话 + 1 段蒸馏

### X.3 反直觉点 / 常见误解（【蒸馏】）
- 读者最容易错的地方（2-3 个）
- 来自 claim 中的"误区"字段

### X.4 边界 / 什么时候不适用（【原话】+【蒸馏】）
- 这条概念失效的场景
- 替代方案

### X.5 与作者其他概念的连接（【蒸馏】）
- 跳到 worldview 的其他支柱
- 给出连接点而非完整展开（避免越界）
```

### 不允许的结构
- ❌ "步骤 1/2/3" 框架（不是方法）
- ❌ 心路历程片段（那是心境反思）

---

## 2. 方法论（methodology）

### 适用场景
- 介绍一套可复用的方法/原则/决策框架
- 例：示例创作者甲《干爽去油》、《沿途下蛋》

### 结构骨架（6 节）

```markdown
### X.0 方法命名与一句话定义（【原话】）
- 作者原话命名的方法名（"我的 XX 法则"/"三步法"）
- 一句话定义（不展开）

### X.1 步骤拆解（【原话】+【蒸馏】）
- 步骤 1 / 2 / 3 ...
- 每步配原话或 claim 引用

### X.2 适用场景（【蒸馏】）
- 什么时候该用
- 触发条件

### X.3 反例 / 什么时候不适用（【原话】+【蒸馏】）
- 作者原话批评过的反例
- 边界条件

### X.4 常见误区（【蒸馏】）
- 读者最容易用错的地方（2-3 个）
- 100-200 字/误区

### X.5 实操框架（【蒸馏】）
- 把方法拆成 3-5 步可执行动作
- 读者明天就能用
```

### 不允许的结构
- ❌ "案例"小节单独成章（案例用案例分析 type）

---

## 3. 行业判断（industry-analysis）

### 适用场景
- 对某个市场/产品/公司/赛道做判断
- 例：示例创作者甲《苹果为什么不酷了》、《AI 手机路径之争》

### 结构骨架（5 节）

```markdown
### X.0 现象与核心问题（【原话】+【蒸馏】）
- 一句话概括要判断的现象
- 作者的核心论点

### X.1 拆解维度（【蒸馏】）
- 至少 3 个独立分析维度
- 每个维度 1-2 个 claim 作支撑

### X.2 拐点判断（【原话】+【蒸馏】）
- 作者的"什么时候是真正 X 时刻"判断
- 触发拐点的关键变量

### X.3 厂商 / 玩家路径（【蒸馏】）
- 主要玩家的不同策略
- 价值链分配

### X.4 价值迁移与终局推演（【原话】+【蒸馏】）
- 作者对"下一个十年"的判断
- 不确定性的承认
```

### 不允许的结构
- ❌ "实操步骤"小节（这是给读者的指南,不是方法论）
- ❌ 整章只列观点不给拆解

---

## 4. 案例分析（case-study）

### 适用场景
- 讲一个完整三段案例（问题-方案-结果）
- 例：示例创作者甲《格力的渠道改革》、《某学员涨粉案例》

### 结构骨架（4 节）

```markdown
### X.0 案例背景（【原话】+【蒸馏】）
- 时间、地点、人物
- 为什么这个案例值得讲

### X.1 问题（problem）【原话】+【蒸馏】）
- 完整 problem 描述
- 数字 / 现象 / 表层症状

### X.2 方案（solution）【原话】+【蒸馏】）
- 完整 solution 描述
- 关键决策点

### X.3 结果（result）【原话】+【蒸馏】）
- 完整 result 描述
- 数字结果
- 可复盘的经验

### X.4 复用条件（【蒸馏】）
- 什么场景下可以套这个案例
- 什么场景下不适用
```

### 硬约束
- ✅ 必须有完整三段（problem / solution / result）
- ❌ 案例不完整（如缺 result）必须标 `result: "<作者未说>"`
- ❌ 不允许在 case 章节里讲多个案例（每个案例单独一章）

## 5. 心境反思（personal-reflection）

### 适用场景
- 谈作者自己的一段心路/成长/低谷/十字路口
- 例：示例创作者甲《聊聊心境和十字路口》、《突然离职的原因》

### 结构骨架（5 节）

```markdown
### X.0 触发事件（【原话】）
- 是什么事件让作者开始反思
- 具体场景

### X.1 心路历程（【原话】+【蒸馏】）
- 作者当时的心理状态
- 几个转折点
- 不回避矛盾

### X.2 反思与提炼（【蒸馏】）
- 抽象出 1-3 条原则
- 这些原则如何指导后续决策

### X.3 行动 / 改变（【原话】+【蒸馏】）
- 反思后作者做了什么
- 读者的可借鉴动作

### X.4 自我定位（【原话】）
- 这次反思让作者重新理解自己是谁
- 不矫情、不煽情
```

### 不允许的结构
- ❌ 大量行业判断（最多 1 个小节触及）
- ❌ "实操框架"（心境不教方法）

---

## 6. 哲学总纲（philosophy-overview）

### 适用场景
- 顶层世界观 / 第一原理 / 哲学命题
- 例：示例创作者甲《序：此人的大脑如何运作》、任何"末章"

### 结构骨架（5 节）

```markdown
### X.0 操作系统：此人如何看世界（【原话】+【蒸馏】）
- 一段 200-400 字的"操作系统"描述
- 不只是"他说了什么",而是"他怎么想"

### X.1 第一原理（【原话】+【蒸馏】）
- 3-7 条最底层依据
- 每条配 derivation + supporting_claim_ids

### X.2 心智模型（【原话】+【蒸馏】）
- 反复使用的思维模型
- name + structure

### X.3 反信仰（【原话】+【蒸馏】）
- 作者最强烈反对的观点
- 按强度排序

### X.4 决策原则（【蒸馏】）
- 按使用场景分类
- context + rule + examples

### X.5 哲学命题（【原话】+【蒸馏】）
- 一段 200-300 字的人生哲学
- "为什么这个创作者会这样思考"
```

### 硬约束
- ✅ 首章和末章通常都是这个 type
- ✅ worldview 阶段产出的 worldview.yaml 是这一章的源材料

## 7. 章节类型 → 数据字段映射

| type | 必填 source_refs 类型 | extended_thinking 推荐占比 |
|---|---|---|
| 基础概念 | [video_id, claim_id] | 20-30% |
| 方法论 | [claim_id] | 10-20% |
| 行业判断 | [claim_id] | 30-40%（行业判断里"价值迁移"常含扩展） |
| 案例分析 | [video_id, case_id] | 5-10% |
| 心境反思 | [video_id, quote_id] | 10-20% |
| 哲学总纲 | [claim_id, worldview_part] | 30-50% |

> **注**：extended_thinking 占比高不意味着"扩展多"——哲学总章里"作者未明说但可推"的洞见更多。

## 8. 反模式速查

| 错误 | 应该用 |
|---|---|
| 把"AI 手机路径之争"章节套成"定义→原话→反例→误区→步骤" | 改用 `行业判断` type |
| 把"干爽去油"章节套成"现象→拆解→拐点→价值迁移" | 改用 `方法论` type |
| 把"序：此人如何看世界"章节套成"案例三段" | 改用 `哲学总纲` type |
| 把"为什么采访要说虎狼之词"章节套成"实操步骤" | 改用 `心境反思` type |
| 把"格力的渠道改革"章节只讲问题不讲方案 | 改用 `案例分析` type 并补 solution+result |

## 9. 历史教训

> v1.0 没有 chapter_type 概念,所有章节都套"定义→原话→动作→反例→误区→步骤"。
> 这导致示例创作者甲 v3.0 样例里：
>   - 第 1 章"AI 宇宙技术底座"（应该用基础概念）→ 套方法论结构,把"类比"小节挤压
>   - 第 3 章"苹果与 iPhone 行业判断"（应该用行业判断）→ 套方法论结构,缺"拐点判断"
>   - 第 7 章"个人成长/低谷/心境"（应该用心境反思）→ 套方法论结构,变成"自我成长五步法"（很别扭）
>
> v2.0 强制 chapter_type 选择,以上问题彻底消失。
